# Contributing

Thanks for considering a contribution to Awesome Self-Hosted-First Streaming!

## Guidelines

- **Stay on-thesis.** Resources should help someone run their own streaming ingest/transcode/delivery/playback stack — protocols, servers, encoders, packagers, players, or well-argued writing about when self-hosting is worth it and when it isn't.
- **License every entry.** Add an accurate license tag, e.g. `(MIT)`, `(AGPL-3.0)`, `(open spec)` for protocols/standards. If a project is proprietary or open-core (community edition + paid enterprise), say so explicitly — it still may belong in the "What You're Avoiding" section, but never unlabeled as if it were FOSS. If you're not certain of the exact license, say so rather than guessing.
- **Real, working links only.** Check that the project is live and reasonably maintained before submitting.
- **One line of description**, written plainly — what it is and why it fits, not marketing copy.
- **Alphabetical order** within a category.
- **No self-promotion spam.** Adding your own project is fine if it genuinely fits and you disclose it in the PR description.
- **Check for duplicates** before opening a PR.

## How to contribute

1. Fork the repo.
2. Add your entry to the right category (or propose a new category if none fits, and explain why in the PR).
3. Open a PR, or use the ["Suggest a resource"](../../issues/new/choose) issue template if you'd rather not open a PR directly.

## Removing a resource

If a project is abandoned, archived, relicensed away from open source, or no longer fits the thesis, open an issue or PR explaining why.
